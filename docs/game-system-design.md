# 放置冒险游戏：系统设计共识

> 状态：玩法骨架已确认，数值与外围系统待设计  
> 最后更新：2026-08-18  
> 用途：供后续设计、原型和开发 agent 读取。除“待讨论”章节外，本文内容均视为当前已确认的设计约束。

> Demo 实现：主干框架已落在 `src/domain`，实现说明见 `docs/demo-architecture.md`。目录中的宠物、地图、物品和事件均为占位内容，不代表正式世界观或数值。

## 1. 项目定位与边界

这是一个适合工作间隙或处理其他事情时游玩的异步放置冒险游戏。玩家派遣宠物队伍外出，等待一段现实时间后回来处理事件，并在“继续深入”和“见好就收”之间进行风险决策。

核心体验可以概括为：

> 低压力、异步、宠物队伍版的“搜集—冒险—撤离”。

当前只确定玩法，不锁定世界观。

- “探索电脑、虚拟或赛博世界”是候选世界观方案之一，不是已确定设定。
- 系统设计应保持题材无关，避免用世界观反向限制玩法。

### 1.1 平台与技术方向

- 首发形态为浏览器 Web / PWA。
- 核心数值、存档、计时和冒险结算应使用与 DOM 无关的纯 TypeScript 逻辑。
- 渲染与输入层保持独立，为未来使用 Tauri 封装为桌宠预留空间。
- 前期优先用低成本界面验证核心玩法，暂不让美术和桌宠表现拖慢玩法验证。

## 2. 核心设计原则

### 2.1 异步但不惩罚迟到

- 每段行动的等待时间大约为 10 分钟至 2 小时。
- 队伍抵达决策节点后会停下等待玩家。
- 玩家晚回来不会额外受伤、丢失物品或触发连续事件。
- 一次回访应能在约 20–60 秒内完成事件处理与下一步派遣。

### 2.2 风险主要可判断，少部分不可预测

- 好的配队、准备和选择能够提高胜算，但不保证结果。
- 玩家能获得多少事件风险信息由当前地图的三档情报决定；低情报不提供虚假信息。
- 第三档展示每种检定结果的完整概率分布，让玩家能够明确判断是否值得冒险。
- 随机结果必须能够解释，不能只显示“成功”或“失败”。

### 2.3 安全区资产不会被远程倒扣

所有已经安全带回、解锁或培养完成的内容，只会增长，不会被系统永久夺走。

- 宠物不会永久死亡、离队或永久降级。
- 宠物不会获得不可恢复的永久伤残。
- 已有等级、属性、Tag、地图记录、账号解锁和仓库资产不会被失败倒扣。
- 留在仓库里的物品不会被系统随机夺走；玩家主动把物品带出后，它就离开安全区并成为本轮 `cargo`，可以被事件损失、主动丢弃，溃败时也会永久丢失。
- 失败只能影响本轮尚未安全带回的战利品、当前伤势和可恢复状态。
- 已经成功入库的内容不会自动再次进入风险区，只有玩家出发前主动携带才会重新承担风险。

玩家主动使用一次性成长道具不属于“永久损失”：道具的价值会完整转化为宠物的永久 Tag。

### 2.4 不设置纯时间失败惩罚

- 删除“延误”这一失败结果。
- 失败不能通过额外等待时间单纯禁止玩家继续游玩。
- 时间可以作为玩家主动选择某条路线的成本，但不作为随机失败处罚。

## 3. 核心冒险状态机

```text
配队与准备
→ 选择方向或地图
→ 等待抵达无收益的地图入口
→ 从入口的一条或多条路线中选择首个探索目标
→ 等待行进
→ 查看行程报告
→ 处理节点事件
→ 选择下一路线；若当前节点是撤离点，也可立即撤离
→ 重复若干节点
→ 抵达固定终点并强制撤离
→ 整理负重
→ 战利品安全入库
→ 恢复与成长
```

### 3.1 配队与准备

玩家在出发前：

- 从可出勤宠物中组成一支或多支队伍。
- 从仓库选择本轮初始携带物品；不携带时以空背包出发。
- 查看初始负重与格子、队伍三项主属性与四项次要属性、Tag 与当前伤势。
- 在确认出发前可以无成本调整。

确认出发时，初始携带物品从仓库原子扣除并进入本轮背包。数量必须为正整数、不得超过仓库库存，也不得让背包格子超过上限；负重可以超过上限并按既有梯度增加风险。它和本轮战利品承担相同的丢失风险，但重复带回已有物品不会再次提供战利品经验。出发后配队与初始携带物锁定，冒险途中不能从仓库补充或更换。

### 3.2 选择方向或地图

出发前展示玩家已经掌握的信息：

- 已解锁地图的普通节点与普通路线名称、ID 在所有情报档位正常显示。
- 当前选中队伍的有效感知，和本地图配置的 `partial` / `full` 两档阈值，共同决定情报档位；更换队伍后立即重算。
- 第一档不显示行进时间、掉落数量、最高稀有度和事件是否存在；普通路线不可达时只提示“某项属性不足”。
- 第二档显示行进时间和节点是否存在随机事件；普通路线不可达时提示具体哪项属性不足，但不显示数值。
- 第三档额外显示节点基础掉落的准确数量区间、最高可能稀有度、普通路线门槛的阈值与队伍当前值，以及每种数量均为 1 的首次撤离奖励。
- 所有档位都不展示具体可能掉落的物品；第三档的最高稀有度只计算节点自动基础掉落，不包含随机事件或首次撤离奖励。
- 第三档的事件情报与第二档相同，只回答“有 / 无随机事件”，不泄露事件类型与风险。
- 感知不会发现隐藏路线。隐藏路线只在携带所需 Tag 的队伍抵达源节点时临时显现；实际走完后才永久登记到地图，此后没有 Tag 的队伍也能看见，但仍不可通行。

每张地图的起始节点是无收益、无随机事件的路线入口。入口可以配置一条或多条出边，玩家抵达后从多个首层目标中选择；它不计入完成节点数。抵达入口前可以安全取消行动且不会获得收益，开始探索后必须通过撤离才能将本轮成果转入永久资产。

### 3.3 等待行进

- 玩家选定方向后，队伍进入 10 分钟至 2 小时的现实时间等待。
- 行进期间不要求玩家操作。
- 倒计时结束后停在节点，不会自动继续。
- 事件结果在抵达节点时生成并写入本次冒险记录，刷新页面不能重新随机。

### 3.4 查看行程报告

抵达普通探索节点时，系统先按照该节点唯一的掉落配置生成基础战利品。每个节点只能在“每件独立抽取稀有度”和“从组合表抽取最终稀有度构成”两种模式中选择一种，不支持叠加多个掉落组。起始节点不执行本节流程。具体字段、概率算法和物品池过滤规则见 `docs/loot-drop-system.md`。

基础战利品完整进入本轮背包并立即登记图鉴，然后系统抽取并持久化节点事件。玩家回来后首先展示：

- 本段发现的战利品。
- 当前总负重与超载等级。
- 每只宠物的状态变化。
- 被触发的属性、Tag 和路线效果。
- 本段事件结果的简短因果说明。

自动掉落先于事件，因此会改变当前负重和事件风险。玩家可以在选择事件方案前丢弃物品，但不能出售；这使“保留重物承担风险”和“先丢弃换取稳妥”成为节点决策。

### 3.5 处理节点事件

事件提供以下类型的选项：

- 通用选项：所有队伍都能选择。
- 属性选项：属性满足条件后出现，或获得更低风险。
- Tag 选项：拥有对应 Tag 才出现。
- 次要属性选项：不达标时始终可见但置灰；条件信息按三档情报逐步揭示，见 6.5.2。
- 隐藏选项：满足队伍、路线或历史状态的复合条件后出现。

事件选择立即结算，不额外增加一段等待。结算可以改变战利品、伤势、负重、地图状态或后续路线。

### 3.6 事件与路线是两个逻辑操作

默认交互顺序为：

```text
处理当前事件
→ 查看即时结算和队伍新状态
→ 选择下一路线；仅在当前节点是撤离点时可选择撤离
```

原因是事件结果可能改变伤势、负重和战利品，从而改变玩家对下一路线的判断。

- 两个操作应在同一次短会话和同一个页面中连续完成。
- 不应要求玩家为了选择路线再次等待或重新进入页面。
- 当“事件选择”本身就是“路线选择”时，可以合并为一次操作。

节点交互形态包括：

- 普通节点：处理事件，再选择路线；只有标记为撤离点时才额外提供撤离。
- 路线事件节点：事件选项本身就是不同路线。
- 报告节点：只查看结果并选择路线。
- 终点节点：处理最终事件，然后整理负重并撤离。

### 3.7 立即撤离

撤离不需要等待，也不进行随机判定，但只能在显式配置的中途撤离点或固定终点进行。普通探索节点和起始入口不能撤离。

1. 玩家选择撤离。
2. 系统只检查本次保留战利品、首次撤离奖励与原库存合并后的仓库格数，不检查负重或冒险背包格数。
3. 仓库能容纳时，立即完整撤离；即使超重或背包超格也不要求出售、丢弃。
4. 仓库放不下时，玩家可出售仓库中已有物品腾出格子，或就地出售本轮战利品。不可出售物品仍须明确保留或丢弃，不能自动消失；同种物品能合并进现有堆叠时不要求空格。
5. 玩家确认后，保留的战利品立即安全入库，无中间结算区。

撤离是一项确定性承诺：

> 只要玩家决定撤离，就一定能够保住自己最终选择留下的内容。

### 3.8 固定终点

- 每张地图存在一个或多个固定终点。
- 普通探索节点处理完事件后只能继续前进；只有少部分显式标记的中途撤离点可以选择继续或撤离。
- 终点节点处理完最终事件后不再提供继续路线，强制进入撤离整理。
- 撤离点不一定是终点，但终点一定是撤离点。
- 抵达终点不会再发生新的随机失败。
- 伤势和负重仍可能迫使玩家放弃部分本轮战利品。

每个中途撤离点或固定终点可以单独配置一份“首次撤离奖励”；普通探索节点不能配置：

- 奖励归属于具体节点，不归属于整张地图；同一地图的不同撤离点分别记录、分别领取。
- 必须从该节点成功确认撤离才发放。仅抵达节点、继续前进或最终溃败都不会领取，也不会消耗首次资格。
- 奖励在撤离结算时直接产生，不占冒险背包格子和负重，但会参与仓库格子检查。仓库放不下时撤离保持阻塞，奖励不会被截断或吞掉。
- 发放后登记图鉴，并按正常带回物品计入本轮战利品经验。
- 起始入口不是有效撤离点，配置校验会拒绝为它设置撤离或首次撤离奖励。
- 可以配置多种奖励物品，但每种物品的数量必须恰好为 1。

### 3.9 结算

成功撤离后：

- 保留的战利品直接进入仓库。
- 宠物获得经验。
- 已发现的地图节点、路线、终点、线索和图鉴永久记录。
- 带伤宠物开始伤势恢复计时，见 8.4。
- 系统留下一条只读战报。战报不含任何待办操作，也不占用宠物，玩家看完关闭即可。

溃败后：

- 丢失大部分或全部尚未安全带回的普通战利品。
- 宠物可能带伤返回。
- 仓库资产、等级、属性、Tag 不受影响。
- 宠物仍获得已完成节点的基础经验。

## 4. 地图系统

### 4.1 固定拓扑与有限随机事件

- 地图节点、连线、分叉、汇合、隐藏路线和终点的位置固定。
- 地图采用无循环分叉图，不允许通过环路无限刷节点。
- 每次冒险只走固定地图中的一条路径，不会经过整张地图。
- 事件内容从节点指定的有限事件池中随机抽取。

### 4.2 地图深度与宽度

- 深度：一轮从起点到终点实际经过的事件节点数量。
- 宽度：每层的路线选择数量，以及整张地图的节点和终点数量。

地图复杂度随游戏进程逐步提高：

| 阶段 | 单轮深度 | 结构 |
|---|---:|---|
| 地图 1 | 1 个节点 | 无分支，节点兼终点 |
| 地图 2 | 2 个节点 | 第一个节点后出现两条路线 |
| 地图 3–4 | 2–3 个节点 | 多处分叉，少量汇合 |
| 中期地图 | 3–4 个节点 | 多条路线、多个终点 |
| 后期地图 | 3–5 个节点 | 复杂分叉、隐藏路线和特殊终点 |

以上数量指单轮经过的节点数，不是地图总节点数。

- 单个决策点通常展示 2–3 条普通路线，再加少量条件路线。
- 地图整体可以很复杂，但单次选择不应出现大量并列选项。

### 4.3 多终点

终点可以包括：

- 普通终点：容易抵达，收益稳定。
- 高风险终点：路线更危险，奖励更好。
- 条件终点：需要特定属性或 Tag。
- 隐藏终点：先发现线索，再满足条件进入。
- 特殊终点：关联稀有成长道具或账号级解锁。

不同终点应提供不同产出方向，不能只是简单的收益高低排序。

### 4.4 地图推进

- 首次抵达任意普通终点即可解锁下一张地图。
- 每个显式中途撤离点和固定终点可以保留各自的首次成功撤离奖励；普通探索节点不能配置。
- 条件、隐藏和特殊终点属于可选探索目标。
- 前期推进不强制完成整张地图。
- 旧地图通过不同产出、未探索终点和隐藏条件持续保有价值。

### 4.5 地图知识

- 地图解锁后，普通节点与普通连线的拓扑立即可见；它们的细节受感知档位控制。
- 隐藏路线和只由它通往的隐藏节点不会被感知揭示。
- 携带指定 Tag 会在源节点临时显示隐藏路线；实际走完该连线后永久记录。
- 已走过的隐藏路线永久显示，即使当前队伍没有 Tag；没有 Tag 时仍不可再次通行。
- 即使地图已完全探索，具体事件仍保持有限随机。

## 5. 事件系统

### 5.1 事件池

除起始节点外，一个探索节点可以关联一个或多个事件池，也可以不关联事件池。节点战利品先由玩家开箱手动拾取，确认完成或放弃剩余物品后才处理事件/路线/撤离。没有掉落的节点跳过拾取。未关联事件池时，完成拾取后直接进入路线选择；若为终点则直接进入撤离。配置了事件池时，抵达节点先固定事件：

```text
合并节点关联事件池
→ 按队伍次要属性、Tag、地图和历史状态过滤
→ 排除本轮不可重复事件
→ 根据权重抽取
→ 将结果固定到本次冒险记录
```

事件可按纯玩法功能分类：

- 收益事件。
- 风险事件。
- 取舍事件。
- 条件事件。
- 路线事件。
- 稀有事件。
- 固定事件。

一个具体事件可以同时属于多个类型。

### 5.2 有限随机规则

- 同一具体事件在单轮冒险中默认不重复。
- 连续多轮应尽量避免反复抽到同一事件。
- 重要成长内容不能只依赖无限低概率。
- 满足隐藏条件后，可以提高事件权重或保证事件出现。
- 关键节点首次抵达可以使用固定事件，后续再切换随机事件池。
- 事件池耗尽时允许重置，但优先选择本轮未出现的事件。

### 5.3 风险模型

实际公式：

```text
风险值 = 事件选项难度 - 队伍对应主属性 + 超载惩罚 + 伤势惩罚
单骰大失败概率 = D6 中「骰点 < 风险值」的面数 / 6
幸运儿大失败概率 = 单骰大失败概率²
```

- **主属性检定通过软性风险调整生效**，属性低只是更容易失败，不会让选项消失。主属性选项掷 D6，可能得到大成功、成功、失败或大失败。
- **次要属性判定不进入风险公式，也不掷骰。**低于成功门槛时选项置灰。达到成功门槛后必定成功，达到单独配置的大成功门槛后必定大成功。它不会产生失败或大失败；门槛的具体展示规则见下方三档情报。
- **直接离开选项始终可用**，不接受 Tag 或属性门槛，不发放奖励，也不造成伤势或其他事件损失。
- 次要属性条件路线始终可见，不达标时置灰并标明所需数值与当前数值。
- Tag 主要用于解锁特殊事件、路线、选项或改变规则。普通路线不得使用 Tag 门槛；Tag 路线必须标记为隐藏。未走过时，只有携带对应 Tag 的队伍能在源节点发现它；走完后永久显示，但再次通行仍需 Tag。
- 工具类物品能否解锁选项或降低风险，取决于 9.2 的结论，目前没有载体。
- 负重和伤势通常提高风险，不应无理由让通用选项消失。

事件的风险档位由大失败概率决定：

- `0%`：稳妥。
- `> 0% 且 ≤ 30%`：冒险。
- `> 30% 且 < 60%`：危险。
- `≥ 60%`：极其危险。

幸运儿两次掷 D6 取高，只有两颗骰子都落入大失败区间才会大失败，因此必须把两颗骰子的联合概率计入预览。事件情报复用当前地图配置的 `partial/full` 感知门槛：

- 第一档：不显示任何主属性选项的危险信息，只显示“风险未知”。
- 第二档：显示准确风险档位，不显示具体概率。
- 第三档：显示大成功、成功、失败、大失败四种结果的准确概率。

次要属性选项不属于随机风险，选项本身在所有情报档位始终可见，但不显示当前次要属性值，也不显示“必定成功/大成功”：

- 第一档：只有未达到成功门槛时显示“学识不足”；达标时不显示任何条件信息。
- 第二档：只有未达到成功门槛时显示“需要学识达到 X”；达标时不显示任何条件信息。
- 第三档：无论是否达标，始终显示“成功条件—学识达到 X；大成功条件—学识达到 Y”。

其中“学识”替换为选项实际使用的次要属性。若事件选项本身检定感知，感知还会作为该选项的对应主属性进入风险公式。

### 5.4 事件选项类型与结果层级

主属性检定使用四档结果：

1. **大成功**（结果差值 ≥ 6）：获得事件奖励与额外奖励。
2. **成功**（结果差值 3～5）：获得事件奖励。
3. **失败**（结果差值 0～2）：没有奖励，也不产生其他影响。
4. **大失败**（结果差值 < 0）：没有奖励，队伍中随机一只仍可行动的宠物伤势 +1。

结果差值 = 检定骰点 − 风险值。大失败结算伤势后，如果队伍中仍有至少一只宠物可以行动，本轮继续；如果全队都已失能，则立即溃败。

次要属性判定只有成功和大成功：队伍该项次要属性达到 `successThreshold` 时成功，达到更高的 `extraSuccessThreshold` 时大成功；后者必须严格大于前者。直接离开产生独立的“已离开”结果，结束当前事件并进入路线选择或终点撤离。

## 6. 宠物、队伍与出勤

### 6.1 宠物数量和自由组队

- 游戏前期只有一只宠物。
- 随游戏进程推进，玩家能够获得多只宠物。
- **单支队伍最少 1 只、最多编入 3 只宠物。**因此主属性的队友协助最多天然只有 2 点，不再额外设置协助上限常量。
- 玩家可以让宠物单独成队，也可以多只组队。
- 玩家可以集中全部出勤宠物组成一队，也可以拆成多支队伍。

该系统的基本取舍是：

- 集中组队：覆盖更多能力、负重和容错。
- 拆分队伍：同时覆盖更多路线和机会，但单队更脆弱。

单队上限固定为 3；同时存在的队伍数量、跨队总出勤上限和解锁节奏尚未确定。

### 6.2 三项主属性

宠物只有三项通用主属性：

- **体能**：负重、抵抗伤势、救助和搬运失能的队友。
- **感知**：提高地图预览和抵达节点后事件风险的情报等级。
- **技巧**：背包格子、处理复杂事件、解锁技术性方案。

三项主属性各自拥有一条零配置即生效的持续机制：体能决定负重上限，技巧决定背包格子上限，感知决定地图与事件情报等级。这是主属性的准入门槛——**加一点当场就能看见变化**。做不到这一点的能力不应占用属性点，应下沉为次要属性（见 6.5）。

明确不设置“机动”主属性。躲避、撤离和特殊行动可由具体事件或 Tag 表达。

主属性不设置攻击、防御、幸运、魅力、智力等数值。这类差异通过次要属性和 Tag 扩展。

### 6.3 队伍属性结算

队伍属性分成“行动型属性”和“容量型属性”，两者不能混用同一套求和规则。

#### 6.3.1 行动型主属性

地图情报、事件检定和普通路线主属性门槛使用以下公式：

```text
宠物有效主属性 = floor(宠物当前主属性 × 伤势倍率)
队伍行动主属性 = 队内最高有效值 + 其他可行动成员的协助
```

- 正常宠物的伤势倍率为 `1`，受伤宠物为 `0.75`，失能宠物不参与计算。
- 除提供最高值的成员外，每只对应有效属性至少为 1 的可行动宠物提供 `+1` 协助。
- 单队最多 3 只宠物，因此协助总额天然最多为 `+2`，无需再做额外封顶。
- 例如三只宠物的有效体能为 `5、4、2`，队伍行动体能为 `5 + 1 + 1 = 7`，不是 11。
- 同一队伍在计算不同属性时可以由不同宠物提供最高值。例如体能专家负责体能检定，感知专家负责地图情报。
- 一条路线如果同时配置多个主属性门槛，每项分别按上述公式计算。

主属性在各环节的用途：

| 环节 | 使用方式 |
|---|---|
| 选择地图时的情报等级 | 使用队伍行动感知，与地图的两档感知阈值比较 |
| 主属性事件选项 | 使用该选项指定的队伍行动主属性进入风险公式 |
| 普通路线主属性门槛 | 使用对应队伍行动主属性进行硬门槛比较 |
| 事件风险情报 | 使用队伍行动感知与当前地图的 `partial/full` 门槛决定隐藏风险、显示档位或显示完整概率 |

事件风险还会在主属性下降之外单独计算队伍伤势惩罚：每只受伤宠物风险 `+0.5`，每只失能宠物风险 `+2`。因此带伤深入既会削弱相关主属性，也会提高事件整体风险；这层双重影响是有意保留的风险压力。

#### 6.3.2 次要属性

```text
队伍次要属性 = 所有可行动成员中该项次要属性的最高值
```

- 次要属性不相加，也没有队友协助。
- 正常和受伤宠物都提供完整次要属性；受伤不会让硬门槛在一轮中突然下降。
- 失能宠物无法继续执行事件或路线行动，因此不参与次要属性计算。
- 该规则统一用于次要属性事件选项、次要属性路线门槛和事件进入随机池的门槛。
- 例如三只可行动宠物的学识为 `2、5、4`，队伍学识为 `5`。

#### 6.3.3 容量型主属性

负重和背包格子由每名成员分别提供后相加，不使用“最高值 + 协助”规则：

```text
单宠负重 = (5 + 体能 × 1.2) × 伤势倍率
队伍负重 = 所有成员的单宠负重之和 − 4 × 失能成员数量

单宠格子 = 8 + 技巧
队伍格子 = 所有成员的单宠格子之和
```

- 受伤会降低个人负重；失能成员不提供负重，并产生 4 点救援负担。
- 背包格子不受伤势影响，因为背包本身不会因携带者受伤而消失。
- 感知不修改掉落概率。属性只影响信息、行动能力和容量，不改变节点掉落表的随机结果。

因此，多宠队的核心优势是能力覆盖、协助、负重、格子和容错，而不是把所有属性直接相加；高度专精的单宠仍然可以完成适合自己的行动。

### 6.4 属性点与升级

- “体能、感知、技巧”称为主属性。
- 宠物当前数值称为属性值。
- 玩家用于提升属性的成长资源称为属性点。
- 宠物通过升级获得属性点。
- 玩家可以自由把属性点分配到三项属性。
- 高属性可以采用递增投入成本，避免无脑集中单项。
- 属性点可以在安全状态下通过一定成本重新分配。
- 失败、受伤和溃败不会永久降低属性值。

已明确删除“提交任务道具获得属性点”的设计。

- 宠物维度的主属性成长只来自升级。
- 任务奖励属于账号或存档维度。
- 任务不会奖励经验值或宠物属性点。
- 任务可以奖励通用货币、物品、宠物、仓库容量、地图或子系统解锁。

属性点**只能用于主属性**。次要属性不消耗属性点，原因见 6.5.3。

#### 等级与经验

- **等级上限 20**，每级 1 个属性点，因此整局游戏共 19 个属性点。
- 升到下一级需要 **等级^1.4 × 20** 点经验，累计约 10,400 点。
- 满级后不再累计经验，不留用不掉的经验条。

指数取 1.4 是因为后续地图的节点经验会随进度上升（见下），线性曲线会被后期地图的产出直接冲垮；而二次和指数曲线的陡峭段全部落在 20 级以外，在当前上限下根本用不到。

主属性因此是一个**在中期结束的系统**。这是刻意的：主属性的效果是线性的（体能每点 +1.2 负重，技巧每点 +1 格子），上限越高，极端专精能把负重／格子的分水岭推得越远，浪费掉的点数越多。上限 20 时均分加点的分水岭是 0.91，仍在物品分布带内。长线成长由次要属性（上限 20，靠道具）和账号维度承担。

#### 经验的来源

一轮冒险结束时，队伍中**每只宠物都获得全额经验**，不按人数分摊——分摊会逼玩家单宠出勤，与 6.1「集中组队覆盖更多能力」相悖。

成功撤离：

```text
已完成节点数 × 本图每节点基础经验 ＋ 战利品经验
```

溃败：

```text
已完成节点数 × 本图每节点基础经验 × 0.5
```

溃败没有战利品经验——东西没带回来。这与 3.9「宠物仍获得已完成节点的基础经验」一致。

**每节点基础经验**由每张地图通过 `nodeXp` 独立配置，起始入口不计节点数；旧配置省略时按 10 兼容。当前探险者山麓为 10，克格纳为 25。

**战利品经验**按稀有度逐件累加：

| 档位 | 每件经验 |
|---|---:|
| 白·常见 | 0 |
| 绿·罕见 | 0 |
| 蓝·稀有 | 2 |
| 紫·史诗 | 8 |
| 黄·传说 | 30 |
| 红·神话 | 100 |

白绿两档为 0：那是随处可见的东西，不构成见识。

战利品经验的判据是「**成功带出来了**」，而不是「最终躺在仓库里」：

- 入库的算。
- 撤离整理时就地出售的**也算**——卖掉只是换了种变现方式。
- 撤离整理时丢弃的**不算**。
- 溃败遗失的不算。

### 6.5 次要属性

主属性回答“这只宠物有多强”，次要属性回答“这只宠物能进哪扇门”。

共四项：

- **口才**：说服、交涉、请托。
- **学识**：辨识物件、理解机制、读懂符号。
- **勇气**：进入危险区域、直面未知、选择激进方案。
- **狡黠**：欺骗、设局、利用规则空子。

约束：

- 每只宠物都拥有全部四项，只是初始值不同。次要属性不是某些宠物独有的。
- 四项与三项主属性正交，不重复主属性的语义。凡是与体能、感知、技巧语义相邻的能力（力量、夜视、机械、开锁等），一律不新增为次要属性；确有此类内容需求时用主属性硬门槛表达。
- 次要属性不引入战斗语义。

数值上限统一为 20，见 6.5.3。初始值的分配规则尚未确定。

#### 6.5.1 与主属性的分工

| | 主属性 | 次要属性 |
|---|---|---|
| 判定形式 | **软门槛**，进入风险计算，属性低只是更容易失败 | **硬门槛**，不达标即不可选 |
| 反馈时机 | 加点当场可见 | 遇到对应门禁时才兑现 |
| 成长资源 | 属性点（升级获得） | 专用道具 |
| 队伍结算 | 队内最高有效值 + 每名其他可行动成员 `+1`；单队最多 3 只，因此最多 `+2` | **可行动成员中的最高值，不叠加** |
| 伤势影响 | 受伤乘 `0.75` 并向下取整；失能不参与 | 受伤不降低数值；失能不参与 |

次要属性不受“受伤”影响，是因为硬门槛在一轮之内跳变无法向玩家解释：提示刚显示“需要勇气 5，你有 5”，队友受伤后选项变灰，读起来像故障而不是规则。失能代表已经无法行动，因此失能宠物不再提供次要属性。

队伍取最高值而不叠加，使多宠队的价值是**覆盖面**而非碾压——一只擅长的宠物就能带队通过，因此“带谁去”始终是有效决策。这与 6.1 的组队取舍一致。

#### 6.5.2 门禁与可见性

次要属性通过三种门禁作用于内容：

- **事件选项置灰**：选项可见但不可点击。
- **事件在池中被排除**：该事件不参与本节点的抽取。
- **地图路径置灰**：路径可见但不可选择。

可见性是次要属性的核心特征，规则如下：

- 不达标一律**置灰但不隐藏选项**。事件次要属性条件严格遵循 5.3 的三档展示，且不展示当前值；其他门禁遵循各自的信息矩阵。
- **一个门禁只对应一项次要属性**，不会出现同时要求两项次要属性的内容。跨类组合（次要属性 + Tag）允许。
- 抵达节点后，若该节点存在因属性不足而被排除的事件，节点信息中逐条列出：还有够不到的事件。第一档显示“某属性不足”，第二档显示成功门槛，第三档显示事件出现条件；不展示当前值。多个事件分别成条。
- 该提示**沉淀为永久地图知识**（见 4.5）。事件在抵达时才抽取，因此首次只能是事后得知；但记录留存后，玩家在后续的路线选择界面即可据此规划。

由此产生一个必须在内容侧留意的副作用：**被排除的事件不参与抽取，因此次要属性低时节点的可用事件池更小、重复率更高**。这与 5.2 的重复保护存在张力，配置事件池时应保证低门槛事件的数量足够。

#### 6.5.3 成长

- 次要属性**只能通过专用成长道具提升，不消耗属性点**。
- 道具的加成数值必须是道具上的**显式字段**，不得由稀有度推导（同 10.1 的字段独立原则）。内容约定为史诗档 +1、传说档 +3，但该约定属于内容安排，不是规则耦合。
- 次要属性成长道具**可以出售**，与 Tag 成长道具不同。玩家因此面对“换钱还是喂宠物”的取舍。
- 次要属性可自由成长，但存在**统一上限 20**：所有宠物每一项的上限相同，不因宠物而异。

不使用属性点的原因：主属性提供的是每轮都在生效的稳定收益，次要属性提供的是偶尔一次的解锁。即使两者的收益都可见，玩家仍会系统性地低估后者，共用同一份资源会让次要属性变成没人点的死选项。

由于上限统一，防止宠物趋同的责任落在**道具稀缺度**和**属性项数**上：喂满一只宠物需要“项数 × 上限”个点数。四项是刻意压低的数量，每多一项，内容侧就要为它铺足够的门禁，否则该项会成为玩家学会忽略的废点。

**门槛相对于上限的位置即内容分层**：门槛远低于上限的是前期内容，贴近上限的只有专门投入过的宠物才能开启，天然构成后期目标。不需要额外的分层机制。

#### 6.5.4 对内容的要求

四项中有两项依赖世界中存在其他生物：

| 属性 | 成立条件 |
|---|---|
| 口才 | 存在可以对话的对象 |
| 狡黠 | 存在可以欺骗的对象，或可以利用的规则空子 |
| 学识 | 存在可辨识的物件——无人环境下同样成立 |
| 勇气 | 存在危险——无人环境下同样成立 |

因此这套次要属性对世界提出了一个要求：**冒险场景中需要有住户**，而不能全部是无人的搜刮环境。否则口才与狡黠没有内容出口。

## 7. Tag 系统

### 7.1 Tag 的作用

Tag 表达宠物的特殊能力和身份，用于：

- 触发特殊事件。
- 解锁特殊路线。
- 为普通事件增加特殊选项。
- 改变局部玩法规则。

Tag 不承担普通属性值功能，原则上不做简单的“成功率 +5%”。

**Tag 不影响任何主属性。** 不提供负重加成、格子加成，也不整体降低风险——全局降风险等同于“所有主属性 +X”，是同一件事换个名字。负重和格子归体能与技巧，风险归主属性、超载与伤势。这条已在类型层面固化：`TagDefinition` 不保留任何主属性加成字段，写不出来。

Tag 只提供正面收益，不附带负面效果。

当前已确定的局部规则 Tag：

- **幸运儿**：事件检定时掷两次 D6 并取较高结果。队伍中只要存在一个幸运儿就生效，多个幸运儿不增加骰子数量；它不改变风险值、主属性或结果分档。

“万人迷”等其他 Tag 的具体效果尚未设计。

#### Tag 与次要属性的边界

两者都用来解锁内容，但承担的体验完全不同，**不可互相替代**：

| | Tag | 次要属性 |
|---|---|---|
| 量 | 二元，只有有无 | 数值，只有高低 |
| 普遍性 | 专属，后续开发尽量避免宠物之间重复 | 人人都有全部四项，只是初始值不同 |
| 信息 | **隐藏**。触发之前玩家不知道这些内容存在 | **可见**。够不到也看得见；具体门槛按情报档位展示 |
| 玩家体验 | 惊喜 | 目标 |

因此同一件事的两种表达是不同的设计：口才 7 是“这只宠物挺会说话”，万人迷是“这只宠物走到哪都有人喜欢”。前者是刻度上的位置，后者是刻度之外的质变。

内容设计时必须明确选择其一：需要玩家事先看到并为之努力的，做成次要属性门槛；需要玩家在不知情的状态下撞见的，做成 Tag 触发。**不得用隐藏门槛表达次要属性**，那会同时毁掉两套系统的体验。

### 7.2 Tag 数量

| 宠物类型 | 先天 Tag | 可塑造 Tag | 最终上限 |
|---|---:|---:|---:|
| 初始宠物 | 0 | 2 | 2 |
| 后续宠物 | 1 | 1 | 2 |

- 初始宠物是完全由玩家塑造的白板。
- 后续宠物拥有一个固定特色，再由玩家补充一个成长 Tag。
- 所有宠物最终最多拥有两个 Tag。

### 7.3 可塑造 Tag 的获得

可塑造 Tag 不通过行为积累获得。

- 冒险中可以获得稀有的一次性成长道具。
- 每种成长道具对应一个固定 Tag。
- 道具必须成功撤离并入库后才能使用。
- 使用后道具永久消失，对应 Tag 永久绑定到指定宠物。
- 已绑定 Tag 不能拆卸、更换、洗掉或转移。
- 同一宠物不能拥有重复 Tag。
- 与宠物先天 Tag 重复的成长道具不能对其使用。
- Tag 槽已满时不能继续使用成长道具。
- 使用前必须明确展示效果并二次确认。
- Tag 描述必须足够具体，不能依赖“略微提高”“偶尔触发”等无法评估的模糊文案。

成长道具属于一次性永久成长资源，是“不设置日常消耗品”的明确例外。

## 8. 负重、伤势与撤离

### 8.1 负重

- 物品同时使用重量与背包格子/堆叠规则，两者独立。
- 队伍存在有效负重上限。
- 探索与撤离均允许超过负重上限。超载唯一的负面影响是增加事件检定风险，不阻止行进、路线选择或撤离，不额外扣物品、造成伤势或延长时间。
- 超载风险按梯度增加，不采用刚超过一点就突然惩罚的断崖规则。

概念梯度：

- 正常负重：没有额外风险。
- 轻度超载：风险开始增加。
- 中度超载：伤势、事件和严重结果风险进一步增加。
- 重度超载：事件风险显著提高，但不额外封锁路线或撤离。

玩家可以在节点整理背包、丢弃战利品。

### 8.2 伤势

每只宠物独立记录状态：

- 正常：提供完整能力和负重。
- 受伤：能力与负重下降。
- 失能：不再提供能力与负重，并需要队友搬运。

伤势只按一档递进：**正常 → 受伤 → 失能**。伤势 +1 表示进入下一个阶段；已经失能的宠物不会再被选为受伤目标。

受伤会降低有效负重上限，从而可能让原本正常的队伍变成超载。

- 单独行动的宠物进入失能时，本轮进入溃败结算。
- 组队时，只要还有宠物能够行动，本轮就可以继续；队友搬运失能成员时会承担额外负重。
- 所有伤势都可以恢复，不存在永久伤残。

### 8.3 撤离时的资产保护

- 宠物不能被丢弃。
- 搬运失能成员的负担会降低冒险期间的有效负重阈值、提高超载风险，但不限制撤离时可带回的战利品重量。
- 只要队伍仍可行动且仓库放得下，所有选择保留的战利品均可带回，不因伤势导致负重下降而强制放弃。
- 宠物和永久资产仍会安全返回。

### 8.4 伤势恢复

伤势按真实时间自动恢复，一次好转一档，每档各自计时。

- **恢复计时只在基地流逝。** 出发即停表，回到基地才重新开始，因此冒险途中不会自愈。
- 计时使用绝对时间，离线期间照常流逝，长时间不上线可以连续恢复多档。
- **带伤不禁止出勤。** 受伤宠物仍可派遣，只是能力与负重打折、风险更高。只有失能宠物不能出发。
- 玩家可以花费通用货币立刻治愈，费用按当前伤势档位递增，一次付清直接回到正常。
- 受伤只降低主属性，不降低次要属性；失能宠物不再参与任何行动型主属性或次要属性计算（见 6.3 与 6.5.1）。

这条设计同时受两项已确认约束的约束：2.4 不设置纯时间失败惩罚，以及 6.1 前期只有一只宠物。若恢复期间禁止出勤，唯一的宠物受伤就会让游戏完全停摆，那正是 2.4 明令删除的“纯等待惩罚”。因此恢复不阻断游玩，只改变玩家“等它好还是带伤搏一把”的权衡；花钱治疗是加速手段，不是解锁手段。

## 9. 工具与消耗品原则

删除需要长期获取、囤积和反复补货的**必需品**。

不设置以下循环：

- 为每次出发购买药品或食物。
- 失败后重新补充基础消耗品。
- 为维持正常冒险反复刷低级补给。

> **2026-09-17 重新讨论（见 §9.3）**：这条否决的是**必需品循环**，不是「消耗品有用」。
> 关键词是「**为维持正常冒险**反复刷」和「**购买**」。只从冒险掉落获得、纯增益、
> 永不成为通关前提的一次性效果，不属于被否决的范围——它是战利品的一个**出口**，
> 不是出发前的**清单**。食物 buff（§9.3）按这条重新定位，§12 对应条目已加注。

### 9.1 工具不是独立品类

**工具就是带 `tool` 标签的普通物品**，不再是与物品并列的第二套目录分类。

这条已经落地：`ITEM_TAGS` 里有 `tool`，目前 15 件物品带该标签（剪刀、螺丝刀、锤子、扳手等）。因此工具自动继承常规物品的全部性质：

- 有重量，占背包负重和格子。
- 有出售价值，可以卖。
- 可以作为任务提交物。
- 进图鉴。

不设置「购买工具」「升级工具」这类独立循环——工具和其他战利品一样靠冒险获得。

### 9.2 尚未决定：工具物品还剩哪些能力

把工具并入物品之后，原先设想的几项能力失去了载体，需要重新决定要不要保留、以及挂在哪里：

| 原设想 | 现状 |
|---|---|
| 工具占用负重 | 自动成立，物品本来就有重量 |
| 工具解锁事件选项或路线 | **没有载体**。若要保留，需要新增「要求携带某件物品」的门禁字段 |
| 工具每轮有限使用次数 | **没有载体**，物品没有次数概念 |
| 工具可升级 | **没有载体**，且与「不设置独立工具循环」相抵触 |

在这几项决定之前，不要往内容里加任何依赖工具次数或工具升级的设计。

> 代码现状：旧的 `ToolDefinition` / `buyTool` / `upgradeTool` / `toolCharges` 一整套机制
> 已于 2026-08-18 全部删除，连带删掉了事件选项和路线上的工具门禁字段。
> 因此**当前的门禁只有三种**：主属性硬门槛、次要属性、Tag。

### 9.3 食物：战利品的出口，不是必需品

食物是带 `food` 标签的普通物品。它保留常规物品的全部性质（有重量、占格子、可出售、进图鉴），
额外可以被**吃掉**，换取一次性效果。**卖钱还是吃掉，由玩家自己决定**；
哪些食物配效果、配多少，是配表的事，规则层不做稀有度耦合（同 10.1 的字段独立原则）。

食物提供两种互相独立的效果，一件物品可以只有其一、也可以两者都有：

| 字段 | 效果 | 性质 |
| --- | --- | --- |
| `foodBuff` | 提升一项**主属性** | 临时，挂在本次远征上 |
| `foodHeal` | 恢复若干**档**伤势 | 立即，永久改变宠物状态 |

#### 不变量

1. **食物 buff 不影响次要属性。** 次要属性是硬门槛（§6.5.1），食物能抬高门槛就等于
   食物是**钥匙**，那它立刻变回「为了过那扇门必须刷食物」的必需品。
   引擎里 `teamSecondaryStat` 的注释也写着「受伤不会让硬门槛在一轮内跳变」——
   次要属性被刻意设计成一趟之内恒定，临时 buff 会推翻它。
2. **一趟之内 buff 只增不减。** 整趟有效、不中途失效、数值是吃下那一刻的快照。
   三条合起来保证**容量永不回落**：格子是硬限制（超格会阻塞后续行动），
   若 buff 中途失效导致容量缩水，玩家会被卡在节点上、被迫丢弃已经捡到的战利品。
   §2.1 保证「玩家晚回来不会额外……丢失物品」，真实时间计时同样因此出局。
3. **同时只存在一个 buff**，后吃的顶掉前面的。因此加成必须是**可比较的标量**
   （单项 `{stat, amount}`），多项加成会让「顶掉」变成一次盲赌。
4. **buff 加在队伍结算之后**，不逐宠叠加。策划配 `+2` 就是 `+2`，不随队伍人数漂移，
   也完全绕开伤势倍率（逐宠加会引出「buff 要不要乘伤势倍率」这个多余的问题）。
5. **buff 同时影响行动型和容量型属性**（§6.3）：进事件检定风险、路线主属性门槛、
   地图情报等级，也进负重上限和格子上限。因为不变量 2 保证只增不减，所以安全。
6. **治疗不占 buff 槽位**，它是立即结算的一次性效果，不是挂在远征上的状态。

#### 吃的时机

| 场景 | 消耗来源 | 可用效果 |
| --- | --- | --- |
| 行前整备 | 仓库（出发那一刻和携带物一起原子扣除） | 只有 `foodBuff` 有意义 |
| 途中，在节点上 | 背包（吃掉同时腾出负重和格子） | `foodBuff` 与 `foodHeal` |
| 基地 | 仓库 | 只有 `foodHeal` 有意义 |

- 行进途中不能吃——背包本来就只能在节点整理。
- **不能吃战利品浮层里尚未拾取的东西**，必须先捡进背包，否则等于绕开了负重和格子检查。
- 行前整备是「**选定**」而不是「立刻吃掉」：玩家反悔、退回上一步、关掉面板，食物都还在仓库里。

#### 对现有规则的唯一推翻

`healPet` 原本禁止「宠物正在冒险途中接受治疗」。**食物治疗对此开口，花钱治疗不开口**：
钱在基地才请得到医生，食物是随身带的。

## 10. 战利品、图鉴与经济

### 10.1 稀有度

每件物品拥有一个稀有度等级，共六档：

| 档位 | 名称 |
|---|---|
| 白 | 常见 |
| 绿 | 罕见 |
| 蓝 | 稀有 |
| 紫 | 史诗 |
| 黄 | 传说 |
| 红 | 神话 |

稀有度表达的是**获取难度**。

#### 相关性

稀有度与以下两项**大致正相关**：

- 掉落稀有度。
- 值重比，即出售价值除以重量。

这两条是档位分布层面的设计倾向，例如红档物品整体的值重比高于黄档，而不是每件物品都必须满足的逐条约束。允许单件物品成为例外。

因此：

- 不得按单件物品自动校验值重比与稀有度是否匹配。
- 值重比的相关性只在可出售物品之间有意义，不可出售物品不参与该判断。
- 配置工具只需呈现各档位的分布供人工判断，不做硬性拦截。

稀有度与**重量无直接关系**。稀有物品不因为稀有而更重，稀有度不得成为负面效果的来源。

#### 稀有度不是掉落概率

物品自身不携带掉落率。某件物品出现的概率由节点关联的事件池、事件权重和事件选项奖励决定。稀有度只是对该难度的描述性等级，不参与随机计算。

#### 与其他属性正交

以下属性与稀有度**没有因果关系**，必须使用各自独立的显式字段表达：

- 是否可出售。
- 是否为一次性消耗品。

不得由稀有度推断这两项，也不得用“缺少出售价值字段”隐式表达“不可出售”，否则漏填价格与刻意设为不可出售在数据上无法区分。

Tag 成长道具属于红-神话档，但这是内容安排，不是规则耦合。红-神话档必须同时包含可正常掉落且可出售的物品，否则玩家会把该档位误解为“不可出售的特殊道具专属档”。

#### 稀有度承担的两项作用

1. **情绪与收集价值。** 高稀有度物品出现在背包中的那一刻本身即构成正反馈，该价值不依赖档位内有多少件物品。
2. **为“继续深入还是立即撤离”提供可判断的诱因。** 路线与终点会展示稀有度上限，玩家据此判断再走一层是否值得。

撤离时“丢弃哪些战利品”的取舍不由稀有度单独承担。由于稀有度与值重比正相关，单看货币价值会得出唯一解。真正的取舍来自无法折算为货币的价值：

- Tag 成长道具带来的永久成长。
- 任务需要提交的实体物品。

#### 稀有度上限预告

路线与终点的稀有度上限由人工配置，不由事件池自动推导。

因为是手工配置，该字段存在与实际事件池不一致的风险，所以配置校验必须承担兜底责任：手填的稀有度上限与该路线或终点事件池实际可产出的最高稀有度不一致时，配置工具必须报错并拒绝应用。

### 10.2 统一的常规物品

不把“普通物品”和“任务物品”设计为两个互斥类别。

- 每件常规物品具有重量、出售价值、来源和若干用途。
- 常规物品可以出售为唯一的通用货币。
- 任务可以引用任意常规物品作为提交条件。
- 同一种物品可以同时具有出售、任务和其他系统用途。
- 玩家可能先出售某件物品，之后接到需要该物品的新任务，并根据图鉴记录重新寻找。
- 常规物品不会在成功撤离后自动兑换，玩家自行决定保留、出售或提交。
- 同类常规物品可以堆叠。

出售和任务提交都是玩家主动把物品转化为其他永久价值，不属于随机永久损失。

### 10.3 成长道具

存在两类一次性永久成长道具，规则不同，不可混为一谈。

**Tag 成长道具**

- 物品分类使用内置 Tag `trait-grant`（配置台显示“赋予特质”）。
- 极其稀有。
- 只通过关键任务或特定探索目标的首次奖励获得。
- 不进入普通随机事件池反复掉落。
- 不可出售。
- 使用后永久转化为宠物 Tag。
- 获得来源应可预期，不能依赖无限低概率重复刷取。

**次要属性成长道具**

- 专用训练素材的物品分类使用内置 Tag `secondary-growth`（配置台显示“次要属性成长”）。
- 提升指定次要属性，规则见 6.5.3。
- 加成数值是道具上的显式字段，不由稀有度推导。内容约定为史诗档 +1、传说档 +3。
- **可以出售**，因此玩家面对“换钱还是喂宠物”的取舍。
- 宠物该项已达上限时不能继续使用。
- 是否可重复掉落尚未确定。由于存在上限，两种取法都不会造成无限增长。

### 10.4 全局图鉴

图鉴记录玩家曾经获得过的所有物品，不要求物品仍在仓库。

- 任何物品进入本轮背包、作为事件奖励、首次撤离奖励或任务奖励发放时，立即登记并按实际件数增加“累计获得”。
- 从仓库带出、随后重新带回的旧物品不重复累计。
- 之后即使丢弃、出售、提交任务或因溃败遗失，解锁状态与累计获得件数都不会回退。
- 图鉴展示目录中的全部物品。未解锁物品只显示图标剪影和名称“？？？”，不显示稀有度、Tag、描述、重量、价值或累计数量。
- 解锁后显示物品图标、名称、稀有度、物品 Tag、累计获得件数，以及该物品配置的描述、重量和价值信息。低稀有度物品可以不配置描述。
- 图鉴可以记录物品的已知来源、重量、价值和已发现用途。
- 未接触的任务不能通过图鉴提前泄露用途。
- 新任务出现后，已登记物品可以更新为“该任务需要”。
- 图鉴应帮助玩家找到曾经在哪里获得过该物品。
- 图鉴提供按稀有度升序或降序排序的功能。图鉴不按稀有度分组，也不展示各档位的收集进度。

图鉴的收集感来自“遇见过”和反复发现，不来自补齐某个稀有度档位，因此仍不展示“已收集 X/Y”或各档位完成率；累计获得件数是单件物品自己的历史记录。

图鉴与玩家里程碑都采用“首次写入后永久保留”的幂等模式，但不是同一类数据：里程碑记录“玩家做过什么”，用于任务与教程进度；图鉴记录“玩家发现过什么”，需要承载物品、来源和用途等内容信息。两者分别存储，未来可以共用底层的集合写入工具，但不能混用 ID 或业务规则。

因此，物品有两种不同进度：

- 发现过：进入图鉴，成为永久知识。
- 成功带回：进入仓库，成为可以出售、提交或保留的永久资产。

### 10.5 交易

- 经济只设置一种通用货币。
- 常规物品由玩家主动出售，不自动兑换。
- 仓库物品支持锁定，防止误售。
- Tag 成长道具与其他明确标记的关键资产不可出售。

出售确认规则按操作方式区分，不按物品单独判断：

- 批量出售或全量出售时，如果待售物品中包含紫-史诗及以上稀有度的物品，必须提示玩家并要求确认。
- 单独选中一件物品出售时，不提示。

紫-史诗是该提示的固定阈值，写死在规则层，不作为可配置的目录数据。

通用货币的具体产出平衡和消耗用途尚未最终确定。

### 10.6 有限仓库

- 仓库使用格子数量容量，**不限制重量**。重量只在冒险途中的背包上生效。
- 每件物品拥有各自的堆叠上限，由物品显式配置；未配置即为 1，也就是一件占一格。堆叠上限不由重量或稀有度推导。
- 同种物品先堆满一格再占用下一格，不同物品之间不共享格子。
- 仓库容量应相对宽松，用于限制无限囤积，而不是迫使玩家每轮整理。
- 仓库满时不会自动销毁物品。
- **不设置结算区。** 撤离整理界面就是结算界面，玩家在那里直接处置背包内容，确认撤离时战利品一次性进入仓库。
- 仓库放不下时，撤离确认被拒绝，队伍停在整理界面。玩家可以丢弃战利品、就地出售战利品，或出售仓库中已有物品腾出格子。
- 是否放得下按合并后计算：能堆进仓库已有堆的部分不额外占用格子。
- 仓库扩容属于账号或存档维度的长期成长。

### 10.7 背包

背包只存在于冒险途中，同时受两条独立限制：

| 限制 | 来自 | 是否允许超出 | 超出后果 |
|---|---|---|---|
| 负重上限 | 体能 | 允许 | 按梯度提高风险，见 8.1 |
| 格子上限 | 技巧 | 拾取不能超出，事件奖励可超出 | 阻塞继续行进，须先整理；不阻止撤离 |

两条限制的比值（负重上限 ÷ 格子上限）决定谁先卡住玩家：物品的**每格满载重量**高于该比值就先撞负重，低于就先撞格子。因此体能与技巧的系数不能各自单独确定，必须一起看，并对照当前物品的重量与堆叠分布。

- 背包格子上限由队伍的技巧提供。
- 一件物品占几格由该物品的堆叠上限决定，见 10.6。
- 事件奖励始终完整进入背包，不因格子已满而被丢弃或静默消失。
- 奖励导致超格时，不能选择下一路线，直到玩家丢弃物品使格子回到上限以内；若当前节点允许撤离，则仍可正常撤离，入库只受仓库格子约束。
- 该阻塞不扣除任何已获得的收益，不造成伤势，也不触发随机判定。它用“暂停行动”表达代价，而不是用“扣除收获”。
- 冒险途中只能丢弃，不能出售。出售只在撤离整理界面开放，否则负重与格子的取舍会被“随时变现”消解。

## 11. 账号与存档维度成长

任务奖励不作用于宠物属性，而作用于账号或存档。

### 11.1 任务出现与完成条件

- `prerequisiteTaskIds` 控制任务何时出现：配置的全部前置任务完成后，本任务才可见。
- 完成条件可以同时包含提交物品、提交通用货币和目标条件；已配置的条件之间统一采用 AND。
- 提交任务时才真正扣除物品和货币。仅达到持有量不会自动消耗，也不会自动完成任务。
- 第一种目标条件为“首次通关地图”：玩家必须至少一次从该地图的固定终点成功撤离。仅抵达固定终点、最终溃败或从中途撤离点撤离都不算通关。
- 第二种目标条件为“玩家里程碑”：UI 在玩家真实完成某项一次性操作后向引擎上报，写入 `completedMilestoneIds`。当前支持打开探险与任务、库存、宠物状态、图鉴、设置五个面板。
- 里程碑上报幂等、顺序不限并随存档持久化；重复操作不重复计数。达到全部里程碑后任务变为可领取，但不会自动领取。
- 目标条件只读取永久进度，不会在提交任务时被消耗。

### 11.2 任务奖励

- 支持通用货币、物品、地图解锁、宠物解锁和仓库扩容，可任意组合。
- 任务明确不奖励经验值，也不奖励宠物属性点。
- 奖励物品在完成时直接进入仓库并登记图鉴；如果最终仓库容量不足，任务不能提交，不会截断或吞掉奖励。
- 仓库扩容奖励在同一次结算中生效，因此可以为本任务自己的物品奖励提供空间。
- 前置任务引用、目标地图引用和奖励引用必须通过配置校验；前置任务不能形成循环依赖。

已认可的奖励方向包括：

- 解锁更多可拥有或可出勤宠物槽位。
- 提升仓库容量。
- 解锁新地图。
- 解锁新的子系统。

具体任务内容、奖励节奏和长期进程仍由后续配表确定。

## 12. 明确删除或否决的方案

后续 agent 不应在没有重新讨论的情况下恢复以下设计：

- 任务道具奖励宠物属性点。
- 日常药品、食物等需要反复补货的消耗品。（2026-09-17 重新讨论：否决的是**必需品循环**；
  只从掉落获得、纯增益、永不成为通关前提的一次性效果不在此列，见 §9 与 §9.3。）
- 宠物永久死亡、永久离队或永久伤残。
- 永久装备或已入库资产被随机摧毁、遗失。
- 失败结果“延误”或额外纯等待惩罚。
- “机动”作为第四项主属性。
- Tag 附带负面收益。
- 可塑造 Tag 通过行为积累获得。
- Tag 载体作为可拆卸、可更换的装备。
- 撤离过程再次等待或进行随机判定。
- 地图使用可无限循环的路线。
- 所有队伍属性简单相加。
- 事件处理后在玩家看不到新状态的情况下自动承诺下一路线。
- 把普通物品和任务物品设计为互斥类别。
- 普通物品撤离后自动兑换为货币。
- 仓库满时自动销毁或覆盖物品。
- 战利品撤离后停留在独立的“结算区”等待玩家逐件处置。
- 仓库使用总负重容量。
- 由重量或稀有度推导物品的堆叠上限。
- 背包格子已满时，事件奖励被丢弃或不予发放。
- 冒险途中随时出售背包物品。
- 恢复期间的宠物禁止出勤。
- 次要属性消耗属性点提升。
- 在第二、第三档事件情报中隐藏次要属性的具体门槛，或完全隐藏对应选项。
- 单个门禁同时要求两项次要属性。
- 次要属性受伤势影响。
- 次要属性在队伍中相加叠加。
- 新增与体能、感知、技巧语义相邻的次要属性（力量、夜视、机械、开锁等）。
- 主属性承担无法在加点当场体现的能力。
- Tag 提供负重、格子或全局降低风险等主属性加成。
- 各张地图给相同的经验，导致推进到更难的地图没有成长收益。
- 队伍经验按人数分摊。
- 溃败给予战利品经验。

## 14. 实现时必须保持的系统不变量

后续原型和正式实现至少应保证：

1. 玩家未及时回来不能改变已经抵达节点的队伍状态。
2. 一旦玩家选择撤离并完成负重整理，不能再发生随机损失。
3. 已入库资产不能被冒险失败倒扣。
4. 随机事件一旦生成必须持久化，刷新不能重抽。
5. 地图拓扑固定且无循环，事件内容有限随机。
6. 事件处理与路线选择默认分离，事件结果先于路线承诺展示。
7. 低感知只能降低地图与事件的信息精度，不能向玩家提供错误信息。
8. 所有坏结果必须能够解释其主要来源。
9. Tag 永久绑定，属性点允许在安全状态下重新分配。
10. 世界观包装不能侵入或锁死核心规则层。
11. 物品首次进入本轮背包时立即登记图鉴，之后不能回退。
12. 仓库放不下时必须由玩家在撤离整理界面主动处置，系统不能自动销毁或截断入库。
13. 第三档情报中的最高稀有度必须由节点自动基础掉落表和实际候选物品动态计算，不得手工配置，也不得包含事件或首次撤离奖励。
14. 物品是否可出售、是否为一次性消耗品必须由独立字段表达，不得从稀有度或其他字段的缺失中推断。
15. 背包格子超限只能阻塞行动，不能扣除已获得的战利品；事件奖励必须完整进入背包。
16. 伤势恢复计时只在基地流逝，且不得成为出勤的前置条件（失能除外）。
17. 次要属性门禁对应的内容必须始终可见。事件选项的条件信息遵循三档情报，且不显示当前值；完全隐藏内容是 Tag 的职责。
18. 次要属性只能由专用成长道具提升，不得消耗属性点；道具的加成数值必须是显式字段。
19. 次要属性取可行动成员中的最高值，不叠加；受伤不降低次要属性，失能成员不参与。
20. 每项主属性都必须拥有一条零配置即生效、且加点当场可见的持续机制。
21. 战利品经验只在成功撤离时结算，判据是「成功带出来了」：入库的和就地卖掉的都算，丢弃的和溃败遗失的都不算。
22. 队伍中每只宠物获得全额经验，不按人数分摊。
