# 行动面板实现记录

更新：2026-09-10。布局与动效以 `prototypes/expedition-panel.html` 为基准，保留已确认的灰框、无阴影和不显示顶部阶段名称。节点战利品已按玩家最新决定改为手动拾取；其他玩法以系统文档和引擎为准。没有修改策划的地图、物品、节点和事件配置。

## 界面流程

- 固定 760×614，50px 顶栏、504px 内容区、58px 操作栏；灰框、无阴影，主题跟随系统。列表在各自区域内部滚动。
- 初始页顶部「探险 / 任务」，进入探险后隐藏切换标签；不展示当前阶段名称（例如「选择伙伴」）。准备进度用顶栏小圆点，不占用正文。队伍概览可切换多支在外队伍、查看只读战报和继续准备草稿。灯泡定位具体待处理队伍。
- 准备：选 1–3 名可行动且未出勤的伙伴 → 地图情报预览 → 确认唯一入口 → 从仓库挑选随行物品。左键移一件、右键移一组，出发时才原子扣除。
- 地图以左右箭头翻页、下方圆点指示，保持 16:9。首图使用现有手绘底图与节点坐标，连线仍读取真实配置。其他地图或首图新增未知坐标节点时，回退为配置驱动的 DAG 拓扑，不套用错误底图。入口必须在图上点选后才能整备。
- 行进使用真实时间，可关闭面板等待。入口没有掉落/事件；普通节点到达时由 `tick` 一次生成 `arrivalLoot` 快照与 `pendingLoot`，不直接入包。开箱动画结束后，左键拾取一件、右键拾取一组，也可全部拾取；确认放弃剩余物品后才能继续。重启不会重抽。
- 事件：选择 → 判定 → 结果。主属性点击真实 D6，按原型播放 1470ms 切面、跳动、旋转减速与落地动效；幸运儿两骰取高。次要属性自动播放 620ms 指针比对，不掷骰，只可能成功/大成功；直接离开直接进入结果。没有离开选项的事件标注必须处理。
- 看完结果后再选择路线或撤离。只有引擎认可的终点/撤离点可以撤离，入口不可撤离。
- 行进期间背包只读；抵达、待事件和待路线可以确认丢弃。手动拾取受格子容量限制，全部拾取只拿装得下的部分；事件奖励仍自动入包，超格时不截断奖励，由引擎阻止继续行进，但不阻止撤离。超重唯一的负面影响是事件风险上升，不限制撤离保留量。
- 任务读取真实前置条件、物品/货币/目标要求和物品/货币/账号成长奖励。自动出现、不需接取、不增加经验奖励。

## 情报与判定数据

- 地图预览仅含普通路线和真正走过的隐藏路线。当前行动选项则使用 `getVisibleRoutes`，具备特质时可首次选择隐藏路线。
- 地图三档情报使用 `mapInformationTier`，不显示普通可能掉落物品清单。节点、路线悬停或键盘聚焦查看详情；后续配置会自动反映在拓扑与情报里。
- 事件选项提示使用 `getRiskPreview`；不可选项使用 `aria-disabled` 和点击守卫，仍能悬停或聚焦看门槛。次要属性未达标按情报档显示不足/成功门槛；完整档提示成功与大成功两条线。
- `RiskPreview.probabilities` 仅完整档返回，提供四档概率表，不解析中文文案。低档不会展示精确风险值、D6 色带或具体概率。
- `primaryOutcomeForRoll` 是引擎判定、概率枚举、React 色带的共同分档函数；`tools/rule_sync.mjs` 继续检查原型同步。
- 新增可选 `EventResolution.check`，保存真实骰点及受伤前的风险快照，或次要属性值。先保存真实结果，再播短动画；旧结果缺少记录时不补掷骰。全员失能的战报也保存最后事件结果。

## 原子撤离与草稿

- 左侧待处理背包、右侧完整仓库。移动只修改 `keep` 草稿；同名旧库存不可取回，可取回上限永远是本轮 `keep[id]`。
- 左侧剩余为 `sell`。不可售物品必须保留或显式标记 `discard`，标记可以撤销。首次奖励单独展示，预留仓库容量，不占背包负重。
- 有出售或丢弃时，先展示清单、单项金额和合计，再确认；返回不产生任何资产变化。全部入库且无丢弃则直接提交。
- `confirmExtractionPlan(state, expeditionId, {keep, sell, discard})` 要求三组精确覆盖 cargo，所有数量都是正整数。在未提交副本上依次丢弃/出售，再校验最终入库合并后的仓库格数（包含首次奖励），不再校验负重或背包格数，全部成功才返回新存档。
- 复用旧来源扣除、经验、图鉴和首次奖励逻辑：随行旧物品不刷经验，不重复登记节点/事件物品；这里只新增首次奖励获得次数。
- 战报新增可选 `expeditionId / lastResolution / soldCargo / saleRevenue`。战报只读、不占用伙伴，不承担奖励领取。旧战报仍可由概览/库存查看。
- 配队、地图、入口选择、携带、开箱已完成、待选事件方案、结果页面/已读、背包展开、丢弃确认、撤离转移/确认、任务选中项分别存在 UI 存储中。关闭/切换/重启不提交，重启仍先只展示桌宠。战利品剩余数量保存在游戏存档，不依赖 UI 草稿。
- 撤离指纹覆盖 cargo/来源、仓库/容量、队伍状态、首次领取记录及相关配置。变化后取消旧转移/确认并提示重整；提交时从权威存档再校验，防止旧草稿重放。
- 存档新增字段均可选，不提升版本，不清空玩家数据。

## 文件与验收

- `AdventurePanel.tsx`：导航、准备、任务与战报。
- `AdventureMap.tsx / adventureModel.ts`：可见拓扑、情报及草稿纯函数。
- `ExpeditionView.tsx / EventOptionInfo.tsx`：行进、事件、路线及背包整理。
- `ExtractionView.tsx / AdventureItems.tsx`：双栏整理、确认和物品格子。
- `adventurePanel.css / adventurePrototype.css`：独立命名空间，后者落实原型的尺寸、布局与动效，不覆盖其他面板样式。
- `npm test` 包含手动拾取、原子撤离、旧货经验、结果持久化、分档、隐藏路线、搬运守恒测试。
- `npm run test:action`：独立 Electron userData 的完整流程回归与截图，包括重启、低情报、双骰、属性判定、离开、溃败、旧库存保护、确认过期与不可售物品。
- 测试的计时跳转、数值和临时目录仅写入测试 userData，不修改正式 JSON 或玩家存档。
- 原型与实现截图保存在 `artifacts/adventure-prototype-smoke/`，详细映射与引擎契约见 `docs/adventure-prototype-fidelity.md`。
