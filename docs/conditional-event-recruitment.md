# 条件固定事件与现场交付任务

## 已实现规则

- 节点 `fixedEventIds` 为有序列表：抵达后选择第一个满足事件条件的事件，替代该次随机池抽取。没有匹配事件则恢复普通事件池；没有可用事件则直接选路/撤离。起始入口不触发事件。
- 事件 `absentPetIds` 要求存档尚未拥有列出的所有宠物，不检查出征队伍是否携带。原有次要属性事件门槛仍有效。任务前置只影响提示出现，不限制相遇和现场交付。
- 选项 `resolution.type = delivery` 配置 `items` 与 `completeTaskId`。从当前远征 `cargo` 扣物品，不扣仓库；锁定物品拒绝交付，提示先解锁。
- 交付不掷骰，确定成功。扣除物品、扣减同物品的初始携带来源记录、登记事件目标、完成任务和发奖在一次状态事务内完成。任一步失败，不提交任何变化。
- 任务目标为 `{ type: "event-choice", eventId, choiceId }`；永久进度存于 `completedEventChoiceKeys`，键为 `JSON.stringify([eventId, choiceId])`。旧存档补空列表。
- 现场任务只允许本事件目标，不叠加仓库提交、货币提交或其他目标。奖励沿用现有任务系统，包括宠物、物品、货币、地图及仓库容量；物品奖励仍检查仓库空间。
- 新宠物立即出现在基地，不加入正在进行的远征，不改变该队属性/容量。后续溃败不撤销任务与奖励。
- 重复点击由阶段和任务完成记录拦截；另一个队伍的旧交付选项也会置灰，不重复消耗。旧事件仍可选择离开。
- 含交付选项的事件必须保留「直接离开」，未带物品可继续探索、以后再来。

## 后台配置入口

1. 地图 → 节点编辑 → 条件固定事件：添加、移除、上移（调整优先级）。
2. 事件 → 出现条件：勾选尚未拥有的宠物模板。
3. 事件 → 选项 → 结算类型「交付物品并完成任务」：搜索物品/按 Tag 筛选、填写数量、选择关联任务。
4. 任务 → 目标「事件交付」：选择对应事件选项；奖励「加入宠物」复用已有表单。
5. 宠物模板：配置加入时的初始等级、属性、先天特质和成长槽位。

事件和任务互相引用，编辑草稿时可分步配置；发布前校验完整引用。交付没有大成功，不可配置额外奖励。发布校验还会检查物品/宠物/任务/事件引用、正整数数量、入口禁用固定事件及重复目标。
