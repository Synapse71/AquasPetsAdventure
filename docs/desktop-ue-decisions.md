# 桌宠客户端 UE 实施共识

更新：2026-09-09。状态：首轮 UE 访谈已收敛，以下已确认事项作为后续实现依据；本文不是已实现功能清单。

## 文档与代码的关系

本轮用户明确确认的规则以本文为准。视觉和操作细节参照 `assets/ASSETS-HANDOFF.md` 与 `prototypes/` 中的定稿原型，但不能把原型占位数值或自建规则直接带入游戏。真实状态变化必须经过 `src/domain/engine.ts`。有冲突而本文未解决的内容需继续确认。

素材准备：13 段透明宠物动画、93 件物品图标、菜单/属性/灯泡/骰子图标，以及桌宠菜单、状态、库存、行动、图鉴、设置六份原型已存在。

实现进度（2026-09-09）：已完成 Electron 桌宠外壳、可控动画、拖拽与稳定面板布局；五个面板已接入真实操作。行动新增完整准备/行进/事件/路线/原子撤离/任务/战报及草稿恢复；详见 `docs/action-panel-implementation.md`。桌宠主体出发/胜负的一次性演出、地点图鉴、存档导入、自启与音量尚未开放。具体范围与验收记录见 `docs/desktop-client-implementation.md`。

## 平台与桌面形态

- 第一版只在 macOS 上实现与验收，Windows 兼容后续再做。沿用会话此前明确的 Electron 方向。
- 平时只显示宠物本体，灯泡按待办状态出现。行进进度不常驻，只有点击桌宠展开气泡菜单时才一起出现；再次点击、打开面板或失焦时随菜单收起。玩家需要操作时才打开面板。
- 宠物上方行进进度条显示当前路径名（路径配置的 `label`），不是目的地节点名；首次前往起点没有对应路径，显示“前往起点”。
- 宠物不会自主游走或改变桌面位置，只支持玩家拖拽定位；待机动作与探险走路动画均在原地播放。
- 保留 macOS 菜单栏图标，提供显示/隐藏宠物和退出游戏。
- 单击菜单栏图标只打开原生菜单，不直接切换显隐；菜单根据实际窗口状态只显示「隐藏宠物」或「显示宠物」其中之一，并保留「退出游戏」。从设置、窗口关闭或应用激活等其他入口改变显隐时，菜单同步更新。
- 设置面板也必须提供退出游戏入口。
- 隐藏宠物继续挂机，不自动弹出面板。主动退出后，行进时间依旧按现实时间计算；下次启动最多恢复到待决策节点，不自动处理事件或继续选择路线。
- 隐藏后重新显示、退出后重新启动，均只展示宠物，功能面板保持收起；玩家主动打开面板时恢复之前的工作进度。

## 面板尺寸、位置与关闭

- 所有功能面板外框不使用阴影，只保留 1px 灰色（`#aeb2ba`）边框；内部控件与分隔线保持原有样式。
- 桌宠本体不显示矩形焦点框，包括键盘 `:focus-visible` 状态；仍保留键盘激活能力，面板内部控件的焦点提示不受影响。
- 2026-09-10 布局调整：库存顶部使用「库存 / 冒险背包」同级页签，关闭按钮固定在整体顶栏；行动顶栏移除当前阶段名称，正文准备步骤导航保留；设置使用「设置 / 行动记录 / 关于」三个同级页签。
- 保留最新原型的大面板尺寸，不再按旧基线缩为 320–360px。大面板是按需打开的短时操作界面。
- 当前原型基准：状态 500×750px（原型实测约 749px），库存宽 812px，行动宽 760px，图鉴与设置为 760×614px。具体高度以各原型固定外框为准。
- 同一时间只打开一个功能面板。面板内切换页面、展开详情或进入确认步骤不改变外框宽高。
- 优先放在宠物左右有足够空间的一侧，并避开宠物本体。
- 如果左右都放不下，保证面板完整留在屏幕工作区内，允许暂时遮挡宠物；不因为开面板而自动挪动宠物。
- 点击桌面或其他应用时自动收起面板，宠物继续留在原位置。
- 关闭面板保留当前页面与未确认操作，包括配队、选地图、初始携带、待确认加点和撤离整理方案。需要放弃修改时由明确的取消/返回操作处理。
- 关闭、隐藏、恢复不能触发出发、加点、出售或撤离提交。跨启动恢复的 UI 草稿须重新核对真实游戏状态；不得重放已经提交的操作。

## 灯泡与睡眠

- 所有待办共用一个灯泡，不按类型换图标或增加角标，不做灯泡上的选择菜单。
- 点击时的优先级：探险待处理（事件、路线、撤离）→ 可提交任务 → 宠物待分配属性点。
- 灯泡本身静止，处理完当前事项后如还有待办则继续显示。
- **待办只控制灯泡，不控制睡眠。** 行进时间不计入空闲时间，每次行进结束后重新开始 3 分钟无交互倒计时；期间点击则重新计时。停止行进且连续 3 分钟无交互才入睡，有未处理事项也不例外。
- 睡眠期间新出现待办不自动唤醒宠物，只显示灯泡。
- 点击睡着的宠物：醒来动画与快捷菜单同时开始。
- 点击睡眠中的灯泡：醒来动画与对应待处理面板同时开始，不等待 5 秒醒来动画结束。
- 恢复显示/重新启动后，期间抵达产生的待办仍由灯泡提示，不自动打开功能面板。
- 其余待机细节沿用素材交接文档：固定站立帧，静止 6 秒后按权重 2:2:5:5:2 播放五段待机动作，不连续重复上一段；菜单展开期间暂停随机切换。待办不能反复触发注意灯泡的动作或阻止入睡。

## 图鉴

- 收藏品（物品 Tag `collectible`）始终出现在图鉴中；未获得时只显示剪影和“？？？”，隐藏稀有度、描述、Tag 等信息。
- 其他物品获得后才出现在图鉴中，不展示未获得占位。
- 不记录或展示全局或分类收集进度：不展示 X/Y、完成百分比、收藏品完成度等。
- 单件物品的累计获得件数继续记录与展示，依旧读 `itemAcquisitionCounts`。
- 收藏品单独一组并置顶，其余已获得物品按稀有度从高到低分组。收藏品不再按稀有度拆组，避免泄露未获得收藏品的稀有度；所有分组均不显示收集进度。

## 撤离整理

- 撤离不限负重、不检查冒险背包格数，超载只增加冒险事件风险。只在最终入库合并后的仓库格数不足时要求腾出空间或减少入库物品。
- 采用新原型双栏整理：左侧探险背包，右侧仓库。想保留的战利品移入仓库，剩余可出售物品在最终确认撤离时出售。
- 有待售卖物品时先列出清单、单项金额和合计，玩家可返回整理或确认撤离；没有待售卖物品时不加这一步。
- 不可出售物品必须由玩家明确选择入库或丢弃，不能自动售卖或自动丢弃。
- 两栏移动仅修改待确认方案，最终确认时统一校验并结算。取消确认不能产生部分出售、部分扣除或重复奖励。
- 仓库原有物品不能通过取回操作变为本次待售卖战利品；必须区分本轮拟入库数量与原库存数量。
- 关闭面板不提交整理方案，再次打开继续整理。

## 洗点

洗点次数整个存档共用，不按宠物分别计算。任意宠物成功洗点都会推进费用档位。

| 本存档第几次成功洗点 | 通用货币费用 |
|---|---:|
| 1 | 0 |
| 2 | 500 |
| 3 | 2,000 |
| 4 | 10,000 |
| 5 及以后 | 30,000 |

保留面板内二次确认，并展示本次实际费用。只有成功完成洗点才扣费、计次；取消、余额不足、没有已分配属性点均不计次。旧存档没有历史洗点计数，后续迁移不能凭空推断历史付费次数。

## 实现衔接检查

- 2026-09-10：现有两张地图前往起点时间改为 30 秒（`startDurationMs: 30000`），后续路段时间不变。首次派遣和每次到站后选择下一目的地，都先完整播放 `start-explore` 的 121 帧 / 24fps，再进入 walk；点击或打开面板不能打断出发演出。只有恢复已有行程时不重播。动画计时直接读取运行时素材清单，不另写一套时长。

- 动画播放需有可控制的进度和结束事件，以支持待机间隔、一次性动画和睡眠链；现有 `<img>` 循环 WebP 不足以承担完整调度。复用已有帧母版制作运行时资源，不把全量高分辨率母版放进应用包。
- UI 草稿与游戏存档分开保存；所有实际资产变化仍由引擎统一处理。
- 原型里的手动拾取、撤离双栏和骰子动画均需核对真实提交时机。不能为播放动画而再次抽奖，也不能因关闭界面损失或重复获得物品。
- 引擎即时记录节点与事件奖励；双栏撤离已由 `confirmExtractionPlan` 原子提交；收费洗点的存档级次数与扣费逻辑已实现；骰子展示读取持久化的真实 `EventResolution.check`，不重新生成结果。
- 当前美术交接文档中“事件奖励超格后无定义”等描述与既有系统不变量有冲突：已有规则要求奖励完整入包，格数超限阻止下一步行动，不能截断或吞掉奖励。
