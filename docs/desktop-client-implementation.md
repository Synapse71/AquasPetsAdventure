# macOS 桌宠客户端 · 实现记录

更新：2026-09-09。本文描述已实现范围，不替代 `desktop-ue-decisions.md` 的最终产品规则。

## 已实现

- Electron 透明、无框、无系统阴影窗口；原生窗口预留宠物与所有可打开面板的最小包围区域，不使用全屏透明遮罩。收起面板后预留区透明且鼠标穿透。
- 默认置顶；设置可调整置顶与宠物大小（画布 260–420px），关闭设置不会移动宠物。
- 只允许玩家拖拽移动；4px 位移区分拖拽与点击。位置存入 Electron `userData/desktop-preferences.json`，重新启动恢复，越界时收回工作区。
- 根据当前帧透明像素判断宠物命中区域，透明区域通过 `setIgnoreMouseEvents` 让鼠标穿透；面板、菜单和灯泡保持交互。
- 复用现有正式素材，脚下一行五个图标按状态 / 库存 / 行动 / 图鉴 / 设置排列，宽度绑定宠物本体宽；弹出与收回使用既定动画时序。
- 同时只有一个面板；状态 500×750px、库存宽 812px、其他宽 760px，其余面板暂保持高 614px。屏幕不足时缩到工作区内，优先避开宠物，放不下时允许覆盖而不移动宠物。
- 所有功能面板使用 1px 灰色（`#aeb2ba`）外框，无外阴影。
- 点击外部、失焦、Escape 或关闭按钮会收起面板。关闭不会销毁已访问的面板组件。
- 固定站立帧 + 五段加权待机，不连续重复，回固定帧后间隔 6 秒。每次开始新一段行进（首次派遣、到站后选择下一个目的地）都完整播放 start-explore（121 帧 / 24fps），之后原地播放已对齐的 walk。当前路段时间进度仅随点击桌宠后的气泡菜单显示，菜单收起时隐藏；仅重启恢复已有行程时不重播出发动画。
- 停止行进后连续无交互 3 分钟才入睡 → 睡眠循环；每次抵达重新开始空闲计时，不累计途中时间，点击会重置倒计时。点击宠物/灯泡立即唤醒，同时打开菜单/目标面板，不等待动画结束。待办不参与睡眠调度。
- 灯泡优先跳转：探险决策 > 可提交任务 > 待分配属性点。普通战报不算待办。
- macOS 菜单栏图标提供显示、隐藏和退出；设置内也有隐藏、退出。恢复显示时面板收起。
- 游戏继续使用原来的引擎、真实计时与存档。关闭/隐藏面板不提交游戏操作，操作成功后立即保存；退出后重启最多推进至待决策节点。
- 配队草稿、选地图、行动/库存/设置页签单独保存在 UI 存储键下，重启只展示宠物，主动打开面板后恢复。配队/地图恢复时验证 ID，实际出发由引擎再次校验。
- 图鉴按已确认方式分组：收藏品置顶，其余只列出已获得物品并按稀有度降序分组。未知收藏品为剪影与 `？？？`，不显示收集完成度，保留单品累计获得数量。
- 状态面板已移植单栏定稿布局：真实属性图标、经验条、三档伤势/恢复倒计时/付费治疗、有效主属性与划线原值、四项次要属性、负重/格子预览、先天/成长特质与空槽。次要属性不显示上限；主题跟随系统。多宠物通过头部选择器切换，待分配点数灯泡能定位到有点数的宠物。
- 加点改为 UI 草稿：逐项增减、撤销、确认后原子提交；草稿按宠物分别保存，关闭/重载不丢失，真实分配或洗点变化后重新验证，防止旧草稿重放。
- 存档级递增收费洗点已实现：首次免费，然后 500 / 2000 / 10000 / 30000，后续恒为 30000。面板内二次确认；取消、余额不足、无可退点数不扣款不计次。旧存档补 `statResetCount: 0`，不重开存档。
- 库存面板固定 812×614px：顶部「库存 / 冒险背包」页签、货币、战报和关闭按钮；关闭按钮在两个页签中位置一致。库存页左侧七列仓库格子、右侧详情，排序和批量售卖仅在库存页展示。按实际 `stackSize` 拆格并补空格；价值/重量/稀有度排序与升降序、物品 Tag、传说及以上描述使用真实数据和素材，图标缺失有占位，主题跟随系统。
- 左键选中物品同时打开操作菜单；售卖数量与批量清单均在面板内确认。锁定/不可出售物品不能进入批量选择；批量按种类出售全部库存，所有重复堆叠同步勾选。`sellWarehouseItems` 完整校验后一次提交，任意一项不合法均不出售、不收钱，不改变图鉴累计获得数。
- 成长道具按实际效果字段提供使用入口：选择宠物、预览、确认后消耗一件。次要属性满值禁用、溢出明确提示；特质道具标明永久绑定、重复特质和满槽禁用。没有引入新道具数据或改变成长规则。
- 冒险背包是独立可滚动页，格子与明细直接展示、不再折叠或浮层覆盖；无在外队伍时显示空态。负重与格子独立显示和提示超出量，可选择多支队伍。行进中不允许丢弃，抵达/事件待选择/撤离整理时可选数量并确认丢弃；不在这里提供途中出售或跨容器搬运。
- 库存页签、排序、选中项、批量选择和待确认售卖/使用/丢弃保存在 UI 草稿。关闭/重启可恢复；库存数量、锁定、价格、道具效果或相关伙伴状态变化后使旧确认失效，不能重放已完成操作。战报保留为只读弹层，关闭战报不重复发放奖励；移除原库存中的直接花钱扩容入口，仓库扩容沿用任务奖励。

```sh
npm install
npm run start:desktop   # 构建后运行，离线可用，不占用 5173 端口
npm run dev:desktop     # Vite + Electron，热更新；需空闲的 5173 端口
npm run dev             # 仅浏览器 Demo/策划后台
```

开发服务已占用 5173 时，`dev:desktop` 会明确报端口冲突，不会接到未知服务。可关闭此前自己的开发服务，或改用 `start:desktop`。

桌宠采用单实例运行。切换开发/构建模式或加载新的本地构建前，需先通过菜单栏/设置退出当前桌宠；隐藏不会结束进程。

策划后台仍在浏览器的 `http://127.0.0.1:5173/?config=1`，桌面窗口不允许导航到后台或其他页面。

Electron 与普通浏览器存档独立。Electron 开发 URL 与本地构建 file URL 的 localStorage 也相互独立，暂不自动导入/合并。这不会覆盖用户以前的浏览器存档。策划在后台确认覆盖代码内置数据后，需重新构建桌面版才能载入；只改后台草稿不会影响桌面版。

首次运行 Electron npm 包可能还需下载官方平台二进制。当前使用 Electron 44.3.0。

## 素材与代码

- `desktop/main.cjs`：窗口、菜单栏、受限 IPC、位置/偏好保存。
- `desktop/preload.cjs`：固定接口桥接；渲染器没有 Node 权限。
- `desktop/geometry.mjs`：主进程和浏览器共用的布局计算，支持负坐标显示器；`computeNativeLayout` 为原生窗口提供与当前面板无关的稳定包围区域。
- `src/ui/PetDesktop.tsx`：桌宠舞台、透明命中、菜单与灯泡。
- `src/ui/petAnimation.ts`：纯动画调度，无奖励/随机事件逻辑。
- `src/ui/uiState.ts`：与游戏状态分离的 UI 草稿。
- `src/ui/PetStatusPanel.tsx` / `petStatusPanel.css`：状态面板；`petStatusDraft.ts`：草稿校验与预览。引擎提供 `allocateStats` 原子加点、`petStatResetCost` / `resetPetStats` 收费洗点，以及与队伍计算共用的单宠有效属性/派生值函数。
- `src/ui/InventoryPanel.tsx` / `inventoryPanel.css`：库存面板；`inventoryPanelModel.ts`：堆叠、排序、批量选择、待确认操作与过期校验。引擎提供 `sellWarehouseItems` 原子批量售卖；其余锁定、道具使用、丢弃、容量均复用已有接口。
- `public/pet-sprites/`：13 段运行时透明雪碧图与清单，总量约 13 MB。当前调度使用五段待机、walk 与三段睡眠链，共 9 段。
- `tools/build-pet-sprites.py`：从 960×902 PNG 母版生成 300×282、24fps 雪碧图，仅平移对齐原地 walk，不改原始素材。需 Pillow、NumPy 与 SciPy。用户已确认并部署 v2 边缘清理图集；`npm run assets:pet` 使用现有美术 venv 默认开启清理，具体算法与备份见 `pet-edge-cleanup.md`。

Electron 权限边界参考官方 [安全建议](https://www.electronjs.org/docs/latest/tutorial/security) 与 [窗口 API](https://www.electronjs.org/docs/latest/api/browser-window)：开启 context isolation/sandbox、禁用 Node integration、校验 IPC 发送方及参数、拒绝新窗口/外部导航/权限请求。

### 点击时偶发单帧跳动（2026-09-09）

旧实现开关面板时先调用原生 `setBounds`，再通过异步 IPC 更新 React 中宠物的局部偏移。原生窗口移动/缩放与渲染提交不同步，会出现旧原点与新偏移混用的一帧；只检查最终位置的测试无法发现。修复前 12 轮开关实测捕获 13 个偏移帧。

原生布局现在预留所有面板的包围区域，面板开关/切换不再改变窗口边界或宠物局部坐标，也不再调用 `setBounds`。只有拖拽、调整宠物大小、显示器工作区变化等确实需要改变几何的操作才更新原生边界。启动时默认鼠标穿透，指针进入宠物有效像素或可见 UI 时才接收鼠标。这样不依赖延迟、隐藏宠物或强制同步渲染来掩盖竞态；面板可见位置和尺寸沿用原算法。

依赖审计额外发现现有开发工具依赖有 3 条告警（Vitest/mocker 与 nanoid），没有新增 Electron 条目。本轮未进行无关的大版本升级；后续单独处理测试工具升级。审计日期同本文更新日期。
