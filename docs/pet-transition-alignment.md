# 出发 → 行进的横向锚点修正

日期：2026-09-10。

## 原因

在实际 300×282 Canvas 上测量 alpha 躯干带（y=155…238），`start-explore` 第 120 帧的中心 x=111.5，而 `walk` 第 0 帧为 x=150.5。两帧脚底均在 y=267，真实播放时窗口屏幕坐标也相同。因此这是素材内部 39px 的横向不连续，不是窗口布局、缩放或脚底高度变化。

现有打包管线为了原地行走，对 walk 做了横向居中；start-explore 母版则保留拿起旗子后向左移动的轨迹。把这两份运行时素材直接相接，就会从左侧瞬移到右侧。

## 实现

- `src/ui/petFrameAlignment.ts` 保存当前咕嘎素材在 300×282 绘制坐标系中的横向根位移补偿曲线；不是通用角色的自动归一化算法。
- 出发前半段（0–89 帧）不动，避免把升起的旗子推过右边缘；随后沿母版向左移动的轨迹逐步补偿，第 104–120 帧保持 +39px。尾帧因此与现用 walk 首帧锚点重合。
- `PetDesktop` 仅改变 Canvas 内这一片段的绘制 x，不修改 Canvas、Electron 窗口、拖拽位置、尺寸、脚底 y、帧顺序或时长。像素命中检测读取修正后的同一 Canvas。
- 不平移 walk，不按整帧包围盒缩放，不每帧用旗子/镐子的边界重新定位，也不在切换瞬间突然补偏移。待机、睡眠等其他片段保持原样。
- 不覆盖母版 PNG、运行时 WebP 或已确认的白边修复资源；正常重建素材不会丢失这项渲染层修正。若替换动画内容或更改运行时图集尺寸，应重新测量补偿曲线，不能盲用当前数值。

## 验证

使用 diagnose 的真实播放反馈回路复现：修正前 Electron 采样明确检测到 x 从 111.5 跳到 150.5，而窗口坐标和脚底一致。

`npm run test:departure` 采样出发尾帧和 walk 首帧，检查躯干中心、脚底和屏幕坐标差均不超过 1px，并核对补偿没有把可见旗子或身体像素移出 Canvas。原始播放记录与实际 Canvas 截图位于 `artifacts/departure-smoke/departure-frames.json`、`seam-start-explore.png`、`seam-walk.png`。

`src/ui/petFrameAlignment.test.ts` 额外锁定曲线端点、前半段不动、尾部不再突变，以及其他片段不受影响。
