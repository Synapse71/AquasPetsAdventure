# 探险面板原型对齐与手动拾取

更新：2026-09-10。唯一视觉基准：`prototypes/expedition-panel.html`。

## 视觉与交互

本轮采用 design-review 的逐屏对照方法，在同一个 Electron 测试环境中分别打开原型和游戏截图，不以自制示意图替代原型。实际配置内容不同，因此比较布局、比例、操作与动画，不比较任务文案和测试数值。

| 环节 | 实现约定 |
| --- | --- |
| 准备 | 固定 760×614 面板；准备进度位于顶栏，不用正文大块步骤导航 |
| 地图 | 左右箭头、页码圆点、16:9 画布；节点用符号；节点/路线情报放悬停提示 |
| 入口 | 在地图上点击闪烁的唯一入口，再进入行前整备 |
| 整备 | 左仓库、右背包，全高双栏、六列格子；左键一件、右键一组 |
| 行进 | 居中路线、地图、420px 进度条与倒计时 |
| 到达 | 左侧开箱与浮动物品，右侧背包；手动拾取，离开前确认放弃剩余物品 |
| 事件 | 96px 事件说明；选项、判定、结果共用下方区域；风险信息悬停展示 |
| 主属性 | 点击骰子开始；透明底骰面素材；1470ms 切面、跳动、旋转减速；幸运儿两骰取高 |
| 次要属性 | 自动 620ms 指针比对，无掷骰按钮；直接离开选项跳过判定页 |
| 撤离 | 左背包、右仓库；未入库物品列出售清单，最终确认才提交 |
| 战报 | 居中结果、物品明细与收益/经验/伤势汇总；只读，不重复发奖励 |

原型之外保留已确认的产品要求：灰色边框、无面板阴影、不显示顶栏阶段名称、多队伍概览、三档情报屏蔽规则、实际撤离点限制，以及不可售物品的明确丢弃确认。原型注释里的旧玩法不能覆盖引擎规则。

首图用已有底图；后续地图缺少专用底图时使用配置驱动拓扑，不借用首图来伪装地图内容。

## 手动拾取的引擎契约

1. `tick` 到达时只抽取一次战利品与事件，推进随机种子。`arrivalLoot` 是完整掉落快照，`pendingLoot` 是还没拾取的部分。此时不加 cargo、不登记获得次数。
2. `pickupNodeLoot` 精确转移指定正整数数量，检查物品、剩余数量和格子容量；只有成功转移才登记图鉴获得次数。负重仍为软上限。
3. `pickupAllNodeLoot` 按剩余物品顺序，优先利用已有同类堆叠和空格，转移装得下的部分，保留装不下的物品。
4. `finishNodeLoot` 结束拾取；只要仍有物品就必须显式传入放弃确认。放弃部分不入包、不登记获得次数。
5. `pendingLoot` 存在时，即使为 `{}`，也必须先完成拾取步骤。事件、路线、出售、撤离请求与最终撤离均有引擎守卫，不能绕开 UI 直接跳过。
6. 没有掉落的节点直接进入事件/路线/撤离；入口仍无事件、无掉落。事件奖励仍自动入包，不经过宝箱。
7. `pendingLoot` 为可选字段：旧存档没有该字段，表示沿用旧的已入包结果，不重复补发或要求玩家再拿一次。存档版本不升级、不重置。

开箱仅播放素材，不调用随机数生成掉落。骰子的真实结果先由引擎保存，再用展示用随机切面播放动画；重启只重现已存结果，不重掷、不重复发奖励。旧事件结果没有骰子快照时直接显示结果，不伪造骰点。

## 验证入口

- `npm test`：包含 `src/domain/manualLoot.test.ts`，验证守恒、容量、部分拾取、放弃、不可绕过和旧存档兼容。
- `npm run test:action`：独立临时存档运行 Electron 全流程，保存原型与实现截图以及 `result.json` 到 `artifacts/adventure-prototype-smoke/`。
- UI 回归检查地图比例/箭头、入口点选、草稿重启、宝箱重启、骰子中间帧、真实双骰、低情报、次要属性、离开、撤离、确认过期、不可售物品、超格整理、旧结果和溃败后动画。
- 测试不写正式策划数据，不清空玩家存档。
