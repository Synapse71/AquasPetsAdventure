与引擎的对应

阶段机traveling → awaiting-event → awaiting-route → extraction， 对应本页的 行进 / 事件 / 选路线 / 撤离整理；结算页对应只读的 Settlement 战报
撤离点引擎的 requestExtraction() 在任何 awaiting-route 节点都可用—— **每个非终点节点都可撤离**，所以选路线时始终有「就地撤离」；终点 terminal 直接进撤离整理
售卖时机就地售卖发生在撤离整理阶段（soldDuringExtraction），卖掉的照样算战利品经验； 结算页只是战报，没有待办操作
负重 / 格子咕嘎（体能 2 / 技巧 2）→ 负重 (5+2×1.2)=7.4，格子 8+2=10； 格子占用 Σ ceil(数量 ÷ stackSize)

设计决定

  • 全流程一块面板，尺寸恒定。十来个阶段共用同一个 760×506 的壳：顶栏（标题 + 阶段标签 + 派遣步骤点）、 定高内容区（内部滚动）、常驻底部操作行（空闲时 visibility:hidden）。 面板下方有尺寸自检读数，任何阶段切换它都不该变。
  • 派遣做成五步向导（宠物 → 地图 → 起点 → 整备 → 出发），顶栏的步骤点标示进度。 当前只有一只宠物、一张图、一个起点——但多选的 UI 结构都摆出来了，锁定项用置灰示意。
  • 行进态就是面板本身的收敛：内容区只剩路线名、进度条和倒计时。 桌宠头顶的小进度条是另一层表达，不在本页。
  • 事件选项永远不消失。选项上只标判定用的属性，风险与概率收在悬停提示里， 按情报档位分级给；不达标的选项整张置灰。
  • 撤离整理 = 左背包右仓库双栏搬运。放进仓库的入库，留在背包里的就地售卖； 仓库放不下就开不出新格。点确认撤离时先弹一次售卖清单，售出不可逆。
  • 战报只读。结算时一切已经发生完毕，展示 入库 / 售卖所得 / 经验 即可，看完关掉，没有待办。
