加点、伤势倍率、派生值都是真的在算。切换伤势档位可以看到那条最容易被误解的规则： 受伤只削主属性和负重，不削次要属性，也不削格子上限。

有属性点时主属性行右侧出现 + 按钮。

属性设计确认

主属性体能 / 感知 / 技巧。没有上限，所以用数字而不是进度条。 总值 = baseStats + allocatedStats，升级得点手动分配。 受伤势倍率影响：正常 ×1、受伤 ×0.75、重伤 ×0.4、失能 ×0
次要属性口才 / 学识 / 勇气 / 狡黠。不能加点，只能靠专用成长道具。 是「能不能进这扇门」的硬门槛，队内取最高，不受伤势影响
伤势正常 / 受伤 / 重伤 / 失去行动能力。恢复 30 分 / 2 时 / 4 时，只在基地流逝； 花钱速治 200 / 1000 / 4000
负重上限(5 + 体能 × 1.2) × 伤势倍率，队伍相加
格子上限8 + 技巧 × 1，队伍相加，不乘伤势倍率
升级xp ≥ 等级 × 20 升一级，每级 +1 属性点
特质最多 2 个（growthTagSlots: 2）。目前全表只有「幸运儿」一个

这一版的处理

  • 主属性改用数字，去掉进度条。进度条隐含「有上限」这个前提，而主属性无上限—— 画成条就得随便定个满值，玩家会照着那个假的满值判断自己练到几成，是误导。
  • 受伤时同一行显示两个数：大号的当前有效值（红色）+ 小号的划掉原值。 再在分组标题右侧挂一枚 ×0.75 的倍率标签，规则只说一次、不在每行重复。
  • 次要属性不写上限。虽然代码里有 SECONDARY_STAT_CAP = 20， 但玩家关心的是「够不够进这扇门」，写着 2 / 20 会让人误以为要练满， 而门槛可能只要 3。
  • 格子上限那张卡在受伤时刻意不变红，负重卡变红。两张卡并排放， 一红一不红是最直接的对照，比任何文字说明都清楚。
  • 铁律：任何交互都不得改变面板的宽高。 确认按钮不新起一行，而是塞进「主属性」那一行右侧——那行本来就存在， 三种状态（待分配 / 确认分配 / 确认重置）共用同一个固定高度的槽位，只换内容不换高度。 伤势提示条同理常驻，正常时显示「状态良好，可以出发」，受伤时才换成恢复倒计时和治疗按钮。 面板下方有实时尺寸读数，点任何东西它都不该变。
  • 加点是暂存 + 确认两步，不是点一下就落库。点 + 只进暂存， 可以连点几下、先看负重和格子上限怎么变，再决定确认还是撤销；每一项旁边还有单独的 − 可以逐点撤回。 这也顺便解决了误点问题。
  • 重置属性点是有代价的操作，所以用红色确认条单独拦一道。 代价（500 货币）目前是占位——resetPetStats() 现在不收任何费用， 需要系统 agent 补上扣费逻辑并定下是花钱还是花道具。
  • 两处确认都做在面板内，没用浏览器原生 confirm()。 原生弹窗和整套 UI 不搭，而且桌宠是悬浮层，原生弹窗的位置和层级不可控。
  • 属性图标由 GPT Image 2 出，沿用战利品那套扁平粗描边风格， 按外接圆归一化后统一在 18px 显示。「技巧」重出过一版—— 最初画的捏合手势在 18px 下糊成一团，换成五指张开的手掌才立住。
